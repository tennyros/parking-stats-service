# Руководство по использованию сервиса парковки

## Обзор
Сервис парковки предоставляет REST API для управления парковкой, поддерживая различные типы транспортных средств и парковочных мест. Сервис обрабатывает операции въезда/выезда автомобилей, управление местами и формирование отчетов.

### Требования

1. **Java 17+**
2. **Docker и Docker-compose**

### Настройка

**1. Клонируйте репозиторий:**

```bash
git clone https://gitverse.ru/test_cakes/Java-middle-new1.5-vadim_23.git
cd Java-middle-new1.5-vadim_23
```

**2. Скопируйте файл .env:**

```bash
cp .env.sample .env
```

**3. Запустите приложение и PostgreSQL через Docker:**

```bash
# Скопируйте docker-compose.yml файл
cp docker-compose.sample.yml docker-compose.yml  

# Убедитесь, что порты на Вашей системе, указанные в docker-compose, не заняты
# и запустите сборку
docker-compose up --build -d
```

**4. После этого API будет доступно по адресу:**

```url
http://localhost:8081/swagger-ui.html
```

## API Endpoints

### Въезд автомобиля
- **Endpoint**: `POST /api/v1/parking/entry`
- **Тело запроса**:
  ```json
  {
    "licensePlate": "А123БВ",
    "type": "PASSENGER"
  }
  ```
- **Ответ**: 
  ```json
  {
    "licensePlate": "А123БВ",
    "entryTime": "2024-03-20T10:00:00"
  }
  ```
- **Примечания**:
  - Номер автомобиля обязателен и должен быть уникальным
  - Тип автомобиля должен быть одним из: PASSENGER, TRUCK, MOTORCYCLE, SPECIAL
  - Возвращает 400, если автомобиль уже на парковке
  - Возвращает 404, если нет подходящего места

### Выезд автомобиля
- **Endpoint**: `POST /api/v1/parking/exit`
- **Тело запроса**:
  ```json
  {
    "licensePlate": "А123БВ"
  }
  ```
- **Ответ**:
  ```json
  {
    "licensePlate": "А123БВ",
    "entryTime": "2024-03-20T10:00:00",
    "exitTime": "2024-03-20T11:30:00",
    "duration": "PT1H30M"
  }
  ```
- **Примечания**:
  - Возвращает 400, если автомобиль не находится на парковке
  - Длительность в формате ISO-8601

### Генерация отчета
- **Endpoint**: `GET /api/v1/parking/report`
- **Параметры**:
  - `start`: Время начала (формат ISO-8601)
  - `end`: Время окончания (формат ISO-8601)
- **Ответ**:
  ```json
  {
    "totalEntries": 100,
    "totalExits": 95,
    "averageParkingDuration": "PT2H15M",
    "entriesByType": {
      "PASSENGER": 20,
      "TRUCK": 10,
      "MOTORCYCLE": 5,
      "SPECIAL": 5
    }
  }
  ```
- **Примечания**:
  - Время начала должно быть раньше времени окончания
  - Длительность в формате ISO-8601

## Бизнес-правила

### Типы автомобилей
- **PASSENGER**: Обычные легковые автомобили
- **TRUCK**: Крупногабаритные транспортные средства
- **MOTORCYCLE**: Мотоциклы
- **SPECIAL**: Специальные транспортные средства

### Правила парковки
1. Каждый тип автомобиля может парковаться только на предназначенных для него местах
2. Автомобиль не может въехать, если он уже на парковке
3. Автомобиль не может выехать, если он не находится на парковке
4. Парковочные места автоматически назначаются в зависимости от типа автомобиля
5. История парковки каждого автомобиля отслеживается

### Правила валидации
1. Номер автомобиля обязателен и должен быть уникальным
2. Тип автомобиля должен быть допустимым
3. Даты отчета должны быть валидными
4. Время начала должно быть раньше времени окончания

## Обработка ошибок
- **400 Bad Request**: Некорректные входные данные
- **404 Not Found**: Ресурс не найден (например, нет доступных мест)
- **409 Conflict**: Нарушение бизнес-правил (например, автомобиль уже на парковке)

## Рекомендации по использованию
1. Всегда проверяйте коды статуса ответа
2. Корректно обрабатывайте ошибки
3. Используйте правильные форматы даты/времени
4. Проверяйте входные данные перед отправкой
5. Следите за доступностью парковочных мест
6. Отслеживайте время въезда/выезда автомобилей
